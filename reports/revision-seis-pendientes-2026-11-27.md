# Revisión de los seis casos pendientes de Guíame

27 de noviembre de 2026 · Decisión editorial aprobada y aplicada

Conservaría **Appsmith, Sim y Magic UI**. Reubicaría **Awesome Claude Skills y GitNexus**. Propondría retirar **SuperClaude Framework** como ficha activa y conservar un enlace a sus comandos para quien ya lo use.

| Grupo en Guíame | Opción principal | Cuándo mostrar el repo revisado | Decisión |
|---|---|---|---|
| 6 · Aplicaciones internas | ToolJet | Appsmith para paneles con lógica JavaScript y versionado en Git en el plan Free | Conservar |
| 10 · Catálogos de skills | Agentic Awesome Skills | Awesome Claude Skills al conectar servicios mediante Composio | Reubicar |
| 12 · Métodos para agentes de código | Superpowers | SuperClaude Framework como enlace de consulta para instalaciones que usan `/sc:*` | Retirar la ficha |
| 14 · Mapas e índices de código | CodeGraph | GitNexus para explorar flujos y revisar renombrados con el mismo índice, cuando el uso encaje con su licencia | Reubicar |
| 22 · Constructores visuales de agentes | Dify | Sim para flujos con conectores y un cliente de macOS que puede conectarse al despliegue propio | Conservar |
| 113 · Componentes animados para React | React Bits para efectos y Magic UI para bloques de página | Magic UI si se necesita una cuadrícula de funcionalidades, un bloque de video o un registro de componentes bajo MIT | Conservar |

Comparé los seis pendientes con sus vecinos editoriales y alternativas enlazadas, usando los README de 27 repos, documentación oficial, archivos de licencia y árboles de Git en los casos donde el contenido publicado era decisivo. Revisé las fichas, temas prácticos, recetas y combinaciones de Alexandría. La evidencia es documental. Quedan por medir en una instalación propia la compatibilidad de conectores, la cobertura de los grafos en un repo real y cualquier dependencia de `/sc:*` en proyectos privados. Las seis decisiones figuran en [Guíame](../curation/guiame.json) y el retiro consta en el [registro](../data/retired.json). La [revisión de los 138 grupos](revision-editorial-138-grupos-2026-11-27.md) documenta el punto de partida.

## 6 · Appsmith

El solapamiento con ToolJet es alto. Ambos permiten montar un panel de operaciones con tablas, formularios y consultas a APIs o bases de datos. Appsmith justifica su lugar cuando el equipo necesita lógica de interfaz en objetos JavaScript, un widget clásico con HTML, CSS y JavaScript propio, y control de versiones sin pasar de su plan Free. Ese plan documenta hasta tres repos privados por espacio de trabajo. ToolJet también tiene GitSync y builders visual y React. Su comparativa comercial incluye Git Sync en Team y Enterprise. El código principal de Appsmith publica Apache 2.0 y ToolJet publica AGPLv3. [JavaScript en Appsmith](https://docs.appsmith.com/core-concepts/building-ui/dynamic-ui) · [Widget clásico](https://docs.appsmith.com/reference/widgets/custom) · [Límite de Git en Appsmith](https://docs.appsmith.com/getting-started/setup/manage-plans/downgrade-plan?downgrade-plan-type=remove-license-key) · [Planes de ToolJet](https://tooljet.com/pricing) · [Licencia de Appsmith](https://github.com/appsmithorg/appsmith/blob/76ace5ea8351f914b14efa1706a2b431819f65ad/LICENSE) · [Licencia de ToolJet](https://github.com/ToolJet/ToolJet/blob/HEAD/LICENSE).

**En Guíame.** ToolJet para el panel interno visual general. Appsmith si se quiere versionar el panel y programar validaciones, estados o consultas o incorporar un widget propio. Budibase si el punto de partida son formularios y automatizaciones internas, o si el equipo ya usa Svelte para extender el constructor. NocoDB encaja en la tarea de trabajar sobre datos mediante una interfaz de tablas. En un panel existente, decidir con el conector, el widget y la edición exactos. [Appsmith con Git](https://docs.appsmith.com/advanced-concepts/version-control-with-git) · [GitSync de ToolJet](https://docs.tooljet.ai/docs/development-lifecycle/gitsync/overview/) · [Plugins de Budibase](https://docs.budibase.com/docs/custom-plugin) · [Componentes Svelte de Budibase](https://docs.budibase.com/docs/custom-component) · [NocoDB](https://github.com/nocodb/nocodb).

## 10 · Awesome Claude Skills de Composio

El índice general de enlaces se solapa con otros catálogos. Lo que merece conservarse es la colección incluida en el propio repo. Su árbol íntegro contiene **864 archivos `SKILL.md`, de los cuales 832 están en `composio-skills/`**. La cifra cuenta archivos, y el árbol incluye variantes de nombre para algunos servicios, como Zoho Books. Las fichas inspeccionadas de Calendar y Zoho Books documentan acciones a través de Rube MCP de Composio y requieren conectar la cuenta correspondiente. El README declara Apache 2.0 y señala que algunas skills tienen sus propias licencias. [Árbol al commit revisado](https://github.com/ComposioHQ/awesome-claude-skills/tree/be2a406907dbc61b73e6827ded415c96139d13a2/composio-skills) · [Google Calendar](https://github.com/ComposioHQ/awesome-claude-skills/blob/be2a406907dbc61b73e6827ded415c96139d13a2/composio-skills/googlecalendar-automation/SKILL.md) · [Zoho Books](https://github.com/ComposioHQ/awesome-claude-skills/blob/be2a406907dbc61b73e6827ded415c96139d13a2/composio-skills/zoho_books-automation/SKILL.md) · [Licencias por skill](https://github.com/ComposioHQ/awesome-claude-skills/blob/be2a406907dbc61b73e6827ded415c96139d13a2/README.md#license).

**En Guíame.** Mantener Agentic Awesome Skills como colección amplia e instalable, VoltAgent como directorio que remite a los autores y Awesome Claude Code para hooks, comandos y configuración de Claude Code. El marketplace de Anthropic es la fuente oficial de sus plugins. La colección de wshobson sirve para instalar paquetes de especialistas. Pasaría Awesome Claude Skills a **MCP: conectar herramientas** y **Automatización y flujos**, enlazada desde Composio como colección de guías para sus conectores. La ficha y sus enlaces seguirían disponibles por esa tarea. [Agentic Awesome Skills](https://github.com/sickn33/agentic-awesome-skills) · [VoltAgent](https://github.com/VoltAgent/awesome-agent-skills) · [Awesome Claude Code](https://github.com/hesreallyhim/awesome-claude-code) · [Plugins oficiales de Anthropic](https://github.com/anthropics/claude-plugins-official) · [wshobson/agents](https://github.com/wshobson/agents).

## 12 · SuperClaude Framework

La versión estable documentada es **4.3.1**. Aporta 30 comandos `/sc:*`, modos de trabajo, perfiles especializados e integración opcional con servidores MCP. El proyecto registró actividad reciente. El plugin TypeScript anunciado para v5 seguía descrito como trabajo en curso. El valor más claro de la ficha actual es encontrar los comandos de una instalación existente. [README al commit revisado](https://github.com/SuperClaude-Org/SuperClaude_Framework/blob/82caa9e669217854692c8f9041e96503f39aff24/README.md) · [Versión 4.3.1 en PyPI](https://pypi.org/project/SuperClaude/4.3.1/) · [Propuesta del plugin](https://github.com/SuperClaude-Org/SuperClaude_Framework/issues/419).

**En Guíame.** Superpowers cubre diseño, plan, desarrollo guiado por pruebas y revisión. ECC sirve cuando se quiere un entorno con agentes especializados, skills, reglas, hooks y memoria. gstack cubre un recorrido de producto, pruebas en navegador y lanzamiento. Las skills individuales de Addy Osmani sirven para incorporar prácticas puntuales. Para estos usos, la selección existente cubre lo que llevaría a instalar SuperClaude desde cero. Propondría retirar su ficha por solapamiento editorial, con un enlace de compatibilidad a `/sc:*` en la guía de Claude Code. En el catálogo hay tres alternativas recíprocas y una combinación entrante desde Serena que requerirían revisión al retirar. La revisión no incluyó las instalaciones de los usuarios. [Superpowers](https://github.com/obra/superpowers) · [ECC](https://github.com/affaan-m/ECC) · [gstack](https://github.com/garrytan/gstack) · [Agent Skills de Addy Osmani](https://github.com/addyosmani/agent-skills).

## 14 · GitNexus

El CLI indexa dependencias, referencias y flujos de ejecución, y documenta la previsualización de renombrados semánticos. El visor consulta ese mismo índice mediante el servidor que arranca `gitnexus serve`. El proyecto documenta un frontend alojado y una vía para desplegarlo localmente. El análisis estándar también puede escribir configuración para agentes en el proyecto. La opción `--index-only` omite esos cambios. La licencia publicada es **PolyForm Noncommercial 1.0.0** y el proyecto ofrece licenciamiento comercial por separado. [README al commit revisado](https://github.com/abhigyanpatwari/GitNexus/blob/acf755a1b70ea91208aac9437c2a552579a62b70/README.md) · [Despliegue del visor](https://github.com/abhigyanpatwari/GitNexus/blob/acf755a1b70ea91208aac9437c2a552579a62b70/docs/deployment.md) · [Licencia publicada](https://github.com/abhigyanpatwari/GitNexus/blob/acf755a1b70ea91208aac9437c2a552579a62b70/LICENSE).

**En Guíame.** CodeGraph es la primera opción para consultar símbolos y llamadas con un índice que sigue los cambios del código. Codebase Memory MCP ya cubre el impacto de cambios de Git y ofrece un visor local 3D en beta. Serena cubre renombrados por símbolos y navegación mediante el servidor de lenguaje. Graphify aporta grafos que también incorporan documentación. Repomix sirve para empaquetar archivos y llevar ese contexto a un chat. Reubicaría GitNexus como referencia de **Comprender y revisar código** para quien necesita inspeccionar un flujo y previsualizar un renombrado sobre el mismo índice. La [receta de repos grandes](../human/playbooks/analisis-de-repos-grandes.md) lo muestra como pieza y como sustituto de Repomix. Conviene corregir ambas referencias, incluida la descripción «sin servidor». El adaptador de CLI para análisis es una integración separada de su posición en la receta. [CodeGraph](https://github.com/colbymchenry/codegraph) · [Codebase Memory MCP](https://github.com/DeusData/codebase-memory-mcp#features) · [CBM Lens](https://github.com/DeusData/codebase-memory-mcp/blob/main/graph-ui/README.md) · [Serena](https://github.com/oraios/serena) · [Graphify](https://github.com/Graphify-Labs/graphify) · [Repomix](https://github.com/yamadashy/repomix) · [Adaptador de Alexandría](../src/repo_intelligence/tools/gitnexus_runner.py).

## 22 · Sim

Sim, Dify y Langflow comparten el editor visual de flujos y la posibilidad de exponer flujos o apps como herramientas MCP. Sim y Dify documentan pasos de aprobación humana. Sim aporta un cliente para **macOS 12 o superior** con navegador, terminal y acceso a carpetas autorizadas. Ese cliente también puede conectarse a una instancia propia de Sim. En otros sistemas se utiliza la app web. Los grupos de permisos permiten limitar modelos, herramientas y operaciones por espacio dentro de una organización. Con facturación habilitada requieren Enterprise. La documentación del proveedor detalla cómo activarlos en instalaciones propias sin facturación. [Sim Desktop](https://docs.sim.ai/desktop) · [Desktop en una instancia propia](https://docs.sim.ai/platform/self-hosting/desktop) · [MCP en Sim](https://docs.sim.ai/workflows/deployment/mcp) · [MCP en Langflow](https://docs.langflow.org/mcp-server) · [Flujos, aprobación y MCP en Dify](https://www.dify.ai/workflows) · [Grupos de permisos de Sim](https://docs.sim.ai/platform/enterprise/access-control).

**En Guíame.** Dify para publicar un asistente o una app con documentos. Langflow si el equipo quiere extender el flujo con componentes Python y LangChain. AutoGPT cuando ya trabaja en su plataforma de bloques y plantillas. Sim merece aparecer cuando el flujo combina servicios de trabajo y el usuario necesita interactuar con los archivos o el navegador desde el cliente de Mac. [Dify](https://github.com/langgenius/dify) · [Langflow](https://github.com/langflow-ai/langflow) · [AutoGPT](https://github.com/Significant-Gravitas/AutoGPT) · [Aprobación humana en Sim](https://docs.sim.ai/workflows/blocks/human-in-the-loop).

## 113 · Magic UI

Ambas colecciones tienen componentes animados para React que se pueden incorporar con el registro de shadcn. Hay solapamientos concretos, como listas animadas y efectos de texto. Magic UI documenta bloques de composición como **Bento Grid** y **Hero Video Dialog**. React Bits resulta más práctico para efectos puntuales como **Split Text** y fondos gráficos como **Liquid Chrome**, con variantes JS y TS, CSS y Tailwind según el componente. [Bento Grid](https://magicui.design/docs/components/bento-grid) · [Hero Video Dialog](https://magicui.design/docs/components/hero-video-dialog) · [Catálogo de React Bits](https://github.com/DavidHDev/react-bits).

**En Guíame.** Ofrecer Magic UI para construir una sección y React Bits para añadir un efecto puntual. Se pueden combinar por secciones, eligiendo una sola implementación cuando ambos resuelven el mismo efecto. Para reutilización de componentes como base de un catálogo propio, la ficha debe distinguir tres licencias. El repositorio de Magic UI publica MIT, con conservación de avisos. Magic UI Pro aplica sus propios términos a las secciones y plantillas de pago, que permiten usarlas en sitios o productos comerciales y restringen la redistribución de esos productos de Magic UI. React Bits permite incorporar el código en sitios y productos comerciales, con una cláusula que restringe revender o redistribuir sus componentes por separado. [MIT de Magic UI](https://github.com/magicuidesign/magicui/blob/1278d872938a718a27fd026da314f3c0f48d85e6/LICENSE.md) · [Licencia de Magic UI Pro](https://pro.magicui.design/license) · [Licencia de React Bits](https://github.com/DavidHDev/react-bits/blob/HEAD/LICENSE.md).
