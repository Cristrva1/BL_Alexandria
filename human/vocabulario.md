# Las palabras que vas a encontrar

Un pequeño diccionario para entender una ficha sin tener que aprender programación primero.

## Repo y README

Un repositorio, o repo, es una carpeta de proyecto con historial. Puede contener una aplicación, piezas de código, instrucciones o un curso. El README es su página de presentación y suele enlazar la instalación. Descargar la carpeta no significa haber instalado el programa.

## Aplicación y librería

Una aplicación ofrece una interfaz o un comando para hacer una tarea. Una librería es una pieza de código que alguien incorpora a un proyecto. Si buscas abrir un programa y pulsar botones, comprueba que la ficha describe una aplicación lista o una web disponible.

## Modelo y proveedor

El modelo es el sistema que genera o interpreta contenido. El proveedor es quien lo ofrece. Una aplicación puede dejarte elegir entre varios proveedores o ejecutar un modelo en tu propio equipo.

## Suscripción, API y clave

Una suscripción da acceso a un producto bajo sus límites. Una API permite que otro programa utilice un servicio y puede tener créditos o cobro por consumo. Su clave es una credencial: se guarda en la configuración indicada, sin publicarla. La ficha explica qué ruta está documentada para cada herramienta.

## Skill, plugin y MCP

Una skill aporta instrucciones a un asistente. Un plugin puede agrupar instrucciones y herramientas. MCP es una forma de conectar herramientas y datos a un asistente compatible. Ninguno incluye por sí mismo una cuenta de IA o todas las tarifas de los servicios conectados.

## Terminal, comando y dependencias

La terminal es una ventana donde escribes instrucciones del sistema, como PowerShell en Windows. Un comando es una de esas instrucciones. Las dependencias son programas o piezas que la herramienta necesita primero, por ejemplo Python o Node.js. No pegues un comando hasta saber en qué carpeta y entorno va a ejecutarse.

## Local, nube, Docker y GPU

Local significa en tu equipo; nube significa en un servicio remoto. La interfaz y el modelo pueden estar en lugares diferentes. Docker prepara aplicaciones en contenedores y requiere su propio entorno. Una GPU es un procesador útil para ciertos modelos: la memoria y compatibilidad necesarias dependen del modelo concreto.
